# Adding a Language to Tau-Voice

(For adding a new task *domain* — the other axis — see
[ADDING_A_DOMAIN.md](ADDING_A_DOMAIN.md).)

**A new language is one folder, produced autonomously.** A complete pack is
generated by the `add-a-language` skill, which drives the `tau2 factory` pipeline
end to end (autoform → draft → arm/seed tasks → nativeness review/apply →
finalize → generate-assets → smoke → full run → annotation packet), with human
review gates at the author form and the generated nativeness-rubric packet. The
author form and nativeness packet are **auto-generated** artifacts you can edit
— not hand-authored inputs.

**Task prose is English, in every language.** A language's task sets
(`<domain>_tasks_<lang>.json`) are the domain's English source tasks with
`_<lang>`-suffixed ids and byte-identical prose: english-prompt mode is how
every multilingual run works, so the language lives entirely in the pack.
Task **translation** is retired and its machinery deleted (2026-08-03);
every shipped domain declares `tasks_translated: False`. See
ADDING_A_DOMAIN.md §3 and §6.

```
data/tau2/multilingual/<lang>/
├── pack.yaml                              # personas, prompts, rates, experiments
├── simulation_guidelines_voice_<lang>.md  # re-authored voice guidelines
├── simulation_guidelines_text_<lang>.md   # re-authored TEXT (chat) guidelines
├── <domain>_tasks_<lang>.json             # localized tasks (built by tooling)
└── <domain>_name_map_<lang>.yaml          # optional: identity-variant names
```

A pack drives **both** voice (`--audio-native`) and text (half-duplex chat)
runs. The `draft` stage authors two guidelines files — voice and text — from
the same personas; TTS voices are generated separately and are simply unused
by a text run.

Dropping the folder in registers everything automatically: the pack and its
personas (which become TTS voice personas), the localized voice + text
guidelines, the task set (`<domain>_<lang>`), and a generated run preset
(`multilingual_v1_<name>`) with the matched English-baseline arm. The shared
test suite picks the language up and enforces every invariant with **zero new
test files**. The acceptance test for this contract is
`tests/test_multilingual/test_no_touch_language_pack.py`.

The reference language is Hindi (`hi/`).

## How to run it: the `add-a-language` skill

Invoke the **`add-a-language`** skill (`.claude/skills/add-a-language/`) — it is
the single source of truth for *how* to run the pipeline, with the review gates
and the modular slots (custom deterministic metrics, language-specific nuances).
This doc explains *what each artifact means* and the genuinely-remaining
human/engineer exceptions; the skill sequences the commands.

## Building several languages in parallel

There is **no shared registry to edit and nothing serializes the languages** —
packs are discovered by globbing `data/tau2/multilingual/*/pack.yaml` and run
presets are derived from each pack's `experiments` entries (see "What you should
never need to touch"). Each language writes only disjoint paths (its `<lang>/`
pack dir and its `<locale>/` voice dir), so concurrent builds never collide. To
build N languages at once:

- Create **one git worktree per language** off the shared integration branch,
  each exporting its own `TAU2_DATA_DIR=<worktree>/data` so factory workspace
  state and generated assets stay isolated per language.
- The root `.env` is **untracked**, so a new worktree does not inherit it — copy
  or `source` it into each worktree first (`set -a; source <wt>/.env; set +a`).
- Run each language's pipeline independently, then merge the pack dirs; because
  the `<lang>/` and `<locale>/` paths are disjoint, the merge is conflict-free.

Note: `tau2 factory` commands buffer output until process exit, so poll `data/`
for new files to track a long stage rather than watching stdout.

## Factory stages (command reference)

The `tau2 factory` commands the skill orchestrates:

1. **Autoform** — `tau2 factory autoform --lang <lang> --display-name <Name>
   --script <script>`: ONE LLM call generates a schema-valid author form (2
   personas spanning a register axis, one male + one female) into
   `data/tau2/multilingual/_factory/<lang>/autoform.yaml`. Review/edit it, or
   re-run with `--hints`. This replaces hand-writing the form.
2. **Draft** — `tau2 factory draft --lang <lang> --form <autoform.yaml>
   [--max-repair-rounds N]`: chained LLM calls draft `pack_draft.yaml`, the
   re-authored **voice** guidelines (Call B), AND the re-authored **text**
   guidelines (Call C) into the `_factory/<lang>/` workspace — all from the same
   Call A personas, so no extra author input is needed for text. The
   deterministic guardrails gate all three, auto-repairing up to `N` rounds
   (default 1; the skill uses 4). Repair is targeted: a voice-guidelines failure
   re-runs only Call B, a text-guidelines failure only Call C, a persona/pack
   failure re-runs Call A and re-derives both.

   Text guidelines are a finalize invariant: every draft carries them (Call C)
   and `finalize` refuses a draft without them. A pre-Call-C pack is fixed by
   regenerating it through the factory, not by backfilling in place.
3. **Validate / edit** — `tau2 factory validate --draft --lang <lang>` after any
   direct edit of the draft; iterate until clean.
4. **Emit the language's task arms** — English source prose, `_<lang>`-suffixed
   ids. Which verb depends on the domain's `curated_source`:
   `tau2 factory arm-tasks --domain airline --lang <lang>` (curated source) or
   `tau2 factory seed-tasks --domain telecom --lang <lang>` (generated pool).
   Both are deterministic and idempotent, and both refuse the other's domains.
   (The translation loop that once produced these was deleted — see
   ADDING_A_DOMAIN.md §6.)
5. **Draft and review nativeness rubrics** — `tau2 factory draft-nativeness
   --lang <lang>` makes
   `data/tau2/multilingual/_factory/<lang>/nativeness_review.yaml` and does not
   edit the pack. The fixed, versioned prompt selects applicable ids from the
   closed catalog and returns only short agent-speech rules plus concrete
   natural/violating examples in the target language. Canonical shared factor
   questions and rules remain catalog-owned. Review every id, rule, and example,
   edit the packet if needed, then change `review_status: pending_review` to
   `review_status: approved` and run `tau2 factory apply-nativeness --lang
   <lang>`. Apply is idempotent and refuses stale packets or any overwrite of
   different existing rubric content. `regional_consistency` is selected only
   when it genuinely applies; when selected, its typed `target_variety` must
   explicitly name and enforce the pack's region/variety (never merely "any
   internally consistent variety"). A pending packet is a hard finalize pause.
6. **Finalize** — `tau2 factory finalize --lang <lang> [--force]`: promotes a
   guardrail-clean draft into `data/tau2/multilingual/<lang>/` (both guidelines
   files — voice and text — first, then `pack.yaml`), re-runs the final-pack
   guardrails, and prints the human-bottleneck checklist.
7. **Generate assets** — `tau2 factory generate-assets --lang <lang>`:
   VOICE-ONLY. Designs + **auto-pins** an ElevenLabs voice for every persona
   (the pack must be exactly one male + one female, tagged `gender`). It needs
   `ELEVENLABS_API_KEY` and the `voice` extra; run `tau2 factory smoke-assets`
   first to confirm the API works. Flags: `--force` (re-pin existing voices),
   `--dry-run`. It flips the `voice_ids` checklist item (and, for a pack with
   no acoustic presets — the default — the trivially-satisfied `noise_wavs`
   item) and re-runs the final-pack guardrails.

   **Locale acoustic beds are RETIRED.** Every language runs on the **shared
   stock-English acoustics** — the same seed-keyed indoor (English TV-news /
   people-talking) and outdoor (street / metro) beds the non-multilingual
   benchmark uses, so acoustics are held constant across languages. A pack
   ships with no `acoustic_presets` (that is the schema default; no shipped
   pack carries any). Locale beds exist only for a pack that explicitly opts
   in (author form `locale_beds: true`), and their generator was deleted on
   2026-08-03 — no shipped pack opted in. A pack that needs locale beds must
   recover the generator from git history.

### The two short-phrase inventories

A persona carries two lists the runtime draws from **uniformly at random with
no context** — `non_directed_phrases` and `backchannel_phrases`. Only the
*timing* is decided in context; the phrase is not. Both are therefore bounded
the same way (a maximum number of entries and a maximum length per entry), and
both bounds are declared once in `tau2.multilingual.brevity` as a
`PhraseInventory`, so the factory guardrails, the parametrized pack-invariant
suite and the redraft verbs all check exactly the same thing.

#### Out-of-turn speech brevity

`non_directed_phrases` — what the caller says AWAY from the phone, to whoever
is in the room with them — is spliced into the live call as one uninterrupted
burst. A sentence-length phrase stops reading as a glance away from the mic and
becomes a second conversation the agent has to sit through, so the channel is
bounded: at most `MAX_NON_DIRECTED_PHRASES` (4) entries per persona, each at
most `MAX_NON_DIRECTED_PHRASE_WORDS` (4) words. Both live in
`tau2.voice_config`; the factory guardrails and the parametrized pack-invariant
suite enforce them, so a draft cannot ship the long form.

"Words" is measured script-aware in `tau2.multilingual.brevity`: space-less
scripts (Han, Japanese, Thai) convert the budget to characters, and Vietnamese
discounts its syllable-tokens. **Onboarding a language in a space-less script
requires adding its factor to `WORD_MEASURES` first** — the guardrail fails
loudly rather than mis-measuring.

Every shipped pack already meets the bound (the packs that predated it were
clipped by a one-shot factory verb, since retired), so there is nothing to run:
the guardrails reject any new pack that exceeds it at write time.

#### Backchannel continuers

`backchannel_phrases` holds at most `MAX_BACKCHANNEL_PHRASES` (2) entries of at
most `MAX_BACKCHANNEL_PHRASE_WORDS` (2) words each (`tau2.backchannel`). The
count bound is the older one and the reason is content: every entry must be a
**pure continuer** — the language's "mm-hmm", meaning "I'm listening, keep
going" and nothing else. An acknowledgment in the list gets drawn at a random
moment; a Mandarin reviewer caught the sim saying 明白了 mid-explanation and the
agent ended the call. The length bound closes the same hole from the other
side: at three or more words a "continuer" has become a turn-level response.
Rich acknowledgment palettes are not lost — they belong in the localization
block's `conversational_confirmations`, where the simulator picks them *in
context*.

Purity is not mechanically checkable, so the reviewed set of record is pinned
per persona in `REVIEWED_CONTINUERS` (`tests/test_multilingual/
test_pack_invariants.py`); changing a pack's continuer means editing that
catalog deliberately. Prefer SELECTING the continuer from material the pack
already has. When a pack contains none anywhere — Italian shipped with only
acknowledgments and speaker-side fillers — author one through the verb rather
than by hand:

```bash
tau2 factory draft-continuers --lang <lang>
```

One fixed, versioned prompt is shown every candidate surface (both personas'
current lists and the language-level palettes), must select from them when
anything qualifies, and declares per persona whether it `selected` or
`authored` — recorded in the pack's provenance marker. Add the result to
`REVIEWED_CONTINUERS` once a native reviewer signs it off.

## Remaining human / engineer exceptions

What still needs a human:

- **`SCRIPT_RANGES` extension**: a script no shipped language uses yet needs
  one engineer-reviewed line in `tau2.multilingual.invariants.SCRIPT_RANGES`.
  (`latn`, `deva`, `hans`, `hant`, `arab`, `cyrl`, `hang`, `jpan`, `thai` are
  already registered.)
- **Locale ambience (retired)**: locale beds are not used — every language
  runs on the shared stock-English acoustics, and the bed generator was
  deleted on 2026-08-03.
- **Review gates**: the skill pauses at the auto-generated author form and at
  the nativeness review packet. The latter must be explicitly approved before
  its generated rules can enter the pack. (Task prose needs no review gate —
  the arms carry the domain's already-reviewed English source verbatim.) The
  voice-review annotation packet (`tau2 annotate packets --form voice_review`)
  is an **optional review aid** the pipeline emits either way —
  not required pipeline steps. Voice pinning is automated; a
  human may still re-audition and override a voice via
  `TAU2_VOICE_ID_<PERSONA_ID_UPPER>` or by re-running `generate-assets --force`.

## `translation_guidance` (per-language, optional but recommended)

Register and grammatical gender are injected via the persona prompt
(`pragmatics_clauses` + `tags.gender`), not via translation — translation stays
persona-neutral, and personas are assigned to tasks at runtime. Anything the
*translation* factory needs that the shared templates can't carry lives in
`translation_guidance`:

Freeform author-written text, injected verbatim into all three factory prompts
(translator, fixer, verifier). Home for translation-specific norms the
language-agnostic shared templates can't carry: calque traps and their natural
rewrites, loanword / code-switching policy, measure-word / classifier rules,
script/number conventions, and the language's gendered-verb behavior. For a
gendered language, state the gender rule for BOTH roles — translator/fixer: use
the unmarked/default form (e.g. Devanagari default = masculine), don't bake a
gender, keep it consistent within a text; verifier: that default is CORRECT and
must never be flagged, flag only gender that is inconsistent within one text.
Omit it and only the language-agnostic rules apply; the `hi` pack is a worked
example.

## What the skill produces (checklist)

- [ ] `data/tau2/multilingual/<lang>/pack.yaml` — exactly one male + one female
      persona (tagged `gender`; load-bearing for both the voice invariant and the
      runtime gender clause), voice-design prompts in `tts_voice_prompt`, pack
      prompts, experiments entries
- [ ] `simulation_guidelines_voice_<lang>.md` (re-authored)
- [ ] `simulation_guidelines_text_<lang>.md` (re-authored; auto-drafted by Call C
      and required by `finalize`)
- [ ] Per-language task arms (English prose, suffixed ids) via
      `tau2 factory arm-tasks` / `seed-tasks`, one per domain the language runs
- [ ] `tau2 factory generate-assets --lang <lang>` — voices auto-pinned;
      final-pack guardrails green
- [ ] `pytest tests/test_multilingual/` green (the parametrized suites pick the
      language up automatically)
- [ ] Stage-1 smoke clean → full run → annotation packet (review aid)

Optional, language-specific: an identity-variant task set
(`tau2 factory localize-entities --lang <lang>` + a reviewed
`locale_corpus.yaml`; picked up as the preset's main arm automatically). Every
corpus declares a domestic `phone_number_format` using `#` digit placeholders
(for example `6## ## ## ##`). STRUCTURED_NAME_PHONE domains
such as telecom generate a deterministic, unique number from that template by
default; no separate arm flag is required.

## What you should never need to touch

Any `.py` file. In particular: `user_simulator*.py`, `voice_config.py`,
`config.py`, the evaluators, the providers, the speech-complexity presets,
`registry.py`, `run_presets.py`, or the test suite. If adding your language
seems to require editing any of those, stop — either a pack field already
covers it, or the schema needs a deliberate extension for everyone. The one
sanctioned exception: a line in `invariants.SCRIPT_RANGES` for a script no
shipped language uses yet.
