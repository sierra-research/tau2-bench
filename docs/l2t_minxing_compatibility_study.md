# Minxing Compatibility Study for LLM Tool-Calling L2T Artifacts

Date: 2026-07-21

## Research Question

This study answers:

> Can these LLM tool-calling datasets be represented and executed through Minxing's current implementation?

It does not yet answer:

> Does Minxing's reconstruction/MMD method improve harmful-shift detection for LLM tool-calling?

The experiment is a controlled format and mode-compatibility check. It deliberately does not redesign Minxing's model, does not add a supervised head, does not mix datasets, and does not run 30-epoch training.

## X, S, and Y Definitions

Each dataset is stored as a Minxing-compatible pickle payload:

- `X`: float32 array with shape `(N, d_x)`. This is the model-facing context/features array.
- `S`: `payload["traj"]["s"]`, a float32 array with shape `(N, T)`. Minxing converts this into one-step sequence pairs `o_hist` and `o_next` with `make_sequence_pairs`.
- `Y`: binary success label with shape `(N,)`. In this compatibility study, `Y=1` means benchmark success/safe-style positive and `Y=0` means benchmark failure/negative.

The pickle contract required by Minxing's external-data path is:

- top-level keys: `X`, `y`, `traj`;
- `traj` must contain key `s`;
- `X`, `y`, and `traj["s"]` must share the same first dimension;
- `y` must be binary.

The BFCL and API-Bank pickle files listed below are local ignored derived
artifacts regenerated by the converter scripts. The tau2 compatibility pickle
is also a local ignored prerequisite unless regenerated through the existing
tau2 conversion pipeline. These binary files should not be committed.

| API-Bank | `data/processed/l2t/apibank/apibank_full_l2t.pkl` | `X=(1016, 402)`, `S=(1016, 404)` | API-Bank positive/synthetic-negative API-call label. Balanced counts, but synthetic negatives are not natural LLM failures and should not be overinterpreted as real deployment safety. |

All compatibility runs used the deterministic split logic observed in Minxing's
referenced entry point:

```python
perm = np.random.RandomState(seed).permutation(N)
train_idx = perm[: int(0.8 * N)]
val_idx = perm[int(0.8 * N):]
```

The seed was `1`.

This split is intentionally unchanged for the Minxing compatibility study. The
API-Bank pair-grouped split applies only to the supervised diagnostic baselines,
where a row-level split was found to place 160/508 pairs across train and
validation.

## Minxing Modes

| Requested mode | Minxing model name | Inputs used | Training objective |
|---|---|---|---|
| `proposed_only` | `proposed` | `X` and `S` | `stability_asymmetric_recon(delta=10.0) + lambda_mmd=0.01 * MMD` |
| `label_bce` | `label_bce` | `X` only | Binary cross-entropy on benchmark success label |
| `reconstruction_only` | `reconstruction_only` | `X` and `S` | Plain sequence reconstruction MSE, with `asym_recon_delta=1` and `lambda_mmd=0` |

`label_bce` is an existing Minxing baseline: a standalone MLP classifier over `X`. It does not use `S`, and it is not evidence that the reconstruction/MMD method works for LLM tool-calling.

`proposed_only` and `reconstruction_only` use `X` and `S`. In this compatibility run, `Y` is used to score Minxing's safety-style predictions, not as a new supervised head.

## Format Compatibility

All three datasets are format-compatible with Minxing's current external-data path. The converted payloads load, produce Minxing sequence pairs, train through the selected existing modes, and emit validation metrics under the same deterministic split.

This is the main positive result of the study.

## Semantic Compatibility

Semantic compatibility is not established. `proposed_only` and `reconstruction_only` make safety-style predictions from reconstructed `S` under a fixed threshold and time window. The LLM benchmark labels, however, encode task/tool-call success. Those two notions are not yet proven to match.

The observed sequence-mode collapses should be interpreted as a mismatch between Minxing's current safety definition and the current LLM benchmark success labels. They should not be interpreted as evidence that tau2, BFCL, or API-Bank are invalid datasets.

## Why Sequence Modes Collapse

`proposed_only` and `reconstruction_only` are sequence reconstruction modes. Their classifier is induced by thresholding reconstructed trajectories, not by directly optimizing benchmark success classification. On these converted LLM artifacts, the thresholded sequence score often falls entirely on one side of the decision boundary:

- tau2 sequence modes collapse to `Y=0`;
- BFCL sequence modes collapse to `Y=0`, which is the minority class in validation;
- API-Bank sequence modes collapse to `Y=1`.

This is a compatibility finding, not a model-quality conclusion for harmful-shift detection.

## Label BCE Baseline

`label_bce` provides a meaningful X-only supervised diagnostic baseline because it directly targets `Y`. It is useful for checking whether the numeric `X` representation contains label signal under Minxing's seed split.

It is limited because:

- it does not use `S`;
- it does not test Minxing's reconstruction/MMD hypothesis-testing method;
- BFCL collapses to the validation majority class;
- tau2 underperforms the majority baseline in this short run;
- API-Bank is the only dataset where it slightly exceeds majority and avoids collapse.

## Why 30 Epochs Are Not Currently Justified

The 5-epoch matrix does not justify 30-epoch `proposed_only` or `reconstruction_only` runs. The sequence modes collapse under the current thresholded safety interpretation, so longer training would mostly test whether a semantically mismatched induced classifier remains collapsed.

A cautious 30-epoch follow-up could be considered only for `label_bce` on API-Bank, and even that would answer an X-only supervised baseline question rather than Minxing reconstruction/MMD harmful-shift detection.

Before 30-epoch sequence-mode runs, the next step should be to define and validate a semantic bridge between tool-calling success labels and Minxing's safety score.

## Limitations

tau2 has only 93 filtered examples, with 19 validation samples under the Minxing split. Per-class recall and macro-F1 are therefore unstable.

BFCL has a strongly imbalanced validation split: 28 negatives and 220 positives. A majority predictor reaches 0.887 accuracy, so balanced accuracy and per-class recall are more informative than accuracy.

BFCL irrelevance rows include an abstention criterion: correct behavior is often
free text/no function call, while incorrect behavior is typically a function
call. This call-vs-no-call signal is part of the irrelevance evaluator
definition and should be interpreted separately from non-irrelevance tool-call
competence. The supervised diagnostics now report BFCL all-category,
non-irrelevance, and irrelevance-only results separately.

API-Bank is balanced in this artifact, but the labels are synthetic. Positive results on API-Bank should not be treated as deployment-safety evidence without checking how those synthetic labels were generated and whether they match realistic tool-calling failure modes.

## Recommended Next Action

Keep the current result as a compatibility study. Use `scripts/run_minxing_l2t_compatibility.py` for reproducibility. Do not run 30-epoch sequence-mode experiments until the semantic target is clarified.
