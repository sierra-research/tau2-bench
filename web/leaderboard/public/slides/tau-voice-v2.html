Act 1 · The question

Voice agents are everywhere.

But can they actually do the job?

Voice agents are everywhere right now — OpenAI Realtime, Gemini Live, xAI Grok. They sound charming, they hold conversations. But the question we care about is harder: can they actually complete a customer-service task — reason about the request, call the right tool, modify the database correctly — under realistic audio conditions?

Task benchmarks rigorously verify tool calls and policy adherence, but only in text. We need both, on the same call, with realistic audio.

τ-Voice is the first benchmark to combine three things that have so far been evaluated in isolation: 278 grounded customer-service tasks inherited from τ-bench, a full-duplex orchestration layer with 200-millisecond ticks for real overlap and interruptions, and a controllable voice user simulator with diverse personas and realistic audio. Critically, the tasks, tools, and evaluator are byte-for-byte identical to the text benchmark — so voice numbers plot directly on the same axis as text.
Finding 1

Voice closed 22 pp of the gap to text — in 8 months.

Same 278 tasks. Same deterministic evaluator. The most recent jump (+29 pp in 2 months) tracks the reasoning-unlocks-tool-use pattern we already saw in text.

Because τ-Voice inherits its tasks and evaluator from τ-bench, voice numbers plot directly on the same axis as text. This chart is exactly that view. Each dot is a voice model at its public release date. The dashed green line is the running best — the voice frontier. The two grey horizontal lines are text reference points: the reasoning ceiling at 85% and the non-reasoning baseline at 54%. Eight months ago, the voice frontier was 30%. Today it's 67%. The biggest risk with any new benchmark is: maybe the failures are just simulator artefacts. So we did a manual audit — two raters labelled all 91 failed simulations across two cohorts. The Voice-Fragile cohort is tasks where text passes but voice-Clean fails — that isolates the cost of going voice-native. The Noise-Fragile cohort is tasks where Clean passes but Realistic fails — that isolates the cost of realistic acoustics. In both cohorts, 79 to 90 percent of failures are the agent, not the simulator. The dominant categories are reasoning failures even when transcription is clean, and authentication transcription failures — the agent fails to hear a name spelled letter by letter. The benchmark is measuring real agent limitations.

Because we induce accents through TTS personas, take the absolute numbers as indicative — but the per-provider spread is real.

Voice user simulator

Realistic audio, deterministic recipe.

Tick-based: four generators (noise, bursts, out-of-turn, speech) → mix → muffle → telephony + frame drops. Reproducible from a fixed seed.

Each tick is 200 ms. Four generators run in parallel: background noise from a sound library, Poisson-scheduled bursts and out-of-turn speech, and the user's speech through one of seven personas. They mix, get muffled randomly to simulate phone movement, and then pass through G.711 µ-law and Gilbert-Elliott frame drops. A separate LLM-driven turn-taking policy decides every 2 seconds whether the user interrupts, yields, or backchannels. Critically, this all runs decoupled from wall-clock time — so the user simulator can use the strongest LLM we have, without a real-time budget.

Recurring patterns

Four failure modes we see again and again.

🔤  Authentication transcription

User spells m-e-i-p, agent hears n-e-a-p, lookup fails, agent loops.

🧠  Lost-track-of-multi-step

User asks for two things in one breath. Agent handles the first; never circles back.

💭  Hallucinated completion

Agent says "I've updated your address" — no tool call. Harder to catch in voice; no visible trace.

🤐  Goes silent on you

After repeated auth failures, the agent simply stops responding. The customer hangs up.

Four recurring patterns. Authentication is the most operationally damaging — it gates everything else. Hallucinated completions are the most dangerous — there's no visible trace in voice, no way for the user to spot it.

Limitations

What τ-Voice does not (yet) measure.

English only, TTS-mediated accents

Diverse accents are induced by ElevenLabs personas, not recorded speakers. Absolute numbers are indicative.

No agent speech-quality scoring

We measure what the agent says — not how naturally it says it.

Transcript injection on user side

The user simulator reads the agent's transcript, not its audio. Agent speech was intelligible in 100% of sampled cases — but worth revisiting as voice models get more expressive.

Cascaded baselines

The framework supports cascaded ASR→LLM→TTS pipelines; a head-to-head with audio-native is future work.
